## Product, source, and distribution
- A single Tampermonkey userscript combining MusicBrainz editing helpers. Canonical executable source: `musicbrainz-tools/toolbox/MusicBrainz_ToolBox.user.js`. Native update manifest: adjacent `MusicBrainz_ToolBox.meta.js`. Root `README.md` contains the current pinned installer reference.
- Keep userscript `@name`, `@namespace`, `@downloadURL`, `@updateURL`, and grants stable. Bump `@version` for every code change; mirror version to `.meta.js`, and repin README to a verified script-containing commit. Use Tampermonkey's native update check; no custom update checker.
- Preserve all merged modules: Disc ID auto-selection, cover-art removal, external-link removal, fill dates/worldwide release events, barcode/catalog search, tracklist-versus-recording, recording data to tracks, duplicate edit checking, barcode-versus-linked-release checking, safe recording matcher, linked-provider indicators and associated editing helpers. Never merge Beatport/BPTopTracker importer features into ToolBox.
- A global MusicBrainz request retry layer handles HTTP 503 indefinitely (honor Retry-After; >=5 seconds fallback). Do not bypass it in new requests.
- Browser dependencies: MusicBrainz release/editor UI and web service, Harmony, and Apple Music/Deezer/other public linked providers for applicable lookups. No separate build/install process besides Tampermonkey.
- Persistent state: Tampermonkey GM values (existing modules) and browser localStorage entries under `mb-barcode-link-checker:` for pending release edit tasks (temporary, 1-hour expiry). No local filesystem paths.

## Barcode vs linked releases checker
- Visible on MusicBrainz release-group pages by the Barcode column as "Check barcodes against links"; checks eligible Digital Media releases with barcodes and displays reviewable findings.
- Only treat provider GTIN/UPC as evidence when actually obtained from the linked provider or verified through Harmony; use `equalGtin` normalization. Reverse lookup results must confirm the barcode exactly.
- Do not silently remove unreadable/dead links; manual review is required. A lone provider mismatch may be ambiguous (possibly wrong MusicBrainz barcode) and must not force a change.
- Corrective actions: `replace-wrong-link`, `remove-duplicate-wrong-link`, `move-out`, and `move-in`. Reconcile linked URLs across releases in the same group and preserve the correct target before moving/removing a URL. Open prefilled MusicBrainz release edits for user review; do not submit edits automatically.
- Edit note contract (2026-10-08): the **cause** of removing a mismatched provider URL is the verified barcode difference, *not* the URL also existing on a different MusicBrainz release. For Deezer and any other supported provider, use `Barcode mismatch with <Provider> (MusicBrainz: <old>; <Provider>: <linked GTIN>).` with actual values from linked-page checks. Deduplicate repeated messages. Do not invent GTINs for unreadable providers. Keep other notes concise and include only the ToolBox script link as attribution; drop unrelated Harmony and Apple Music-method citations from the generated edit note. Do not add duplicate "added links" text when a replacement/move-in already accounts for them.
- User-reported regression before 1.0.56: v1.0.55 emitted "Removed a wrongly linked Deezer release URL. The same URL is already correctly linked to: ..." followed by three source URLs; this wrongly presented duplicate linkage as the justification. Fix specifically in `makeEditNote` within the checker module.

## 2026-10-08 - v1.0.59 - One unified Apple Music importer

- User reported **two Apple import buttons** after v1.0.58: Credit Hoarder's Apple source icon inside Toolbox **and** the separate `Apple Music works credits -> MusicBrainz` v2.3.22 panel. User explicitly rejected treating side-by-side features as a merger and required **one Apple entry point, no functionality loss, no duplicate UI, no duplicate Works or edits**.
- **Owner and frontend:** v1.0.59 uses the **Credit Hoarder Apple icon** as the single Apple import action within Toolbox. Its existing artist/entity review table, matching by URL/alias/context/co-credit, deduplication, consolidated multi-source import, role mappings and Instant Fill remain the shared workflow. The Toolbox's outer IIFE sets `document.documentElement[data-karpuzikov-apple-import-owner="toolbox"]` on release relationship editors, suppressing an inactive older `#am2mb-panel` from a simultaneously installed standalone script. An active import with results should not be removed. The standalone updater v2.3.23 detects the marker, defers UI injection and remains a full fallback when Toolbox is absent. **Users should update both installed scripts and refresh a clean tab** to avoid old-version duplicate buttons.
- **Album workflow parity:** The Apple icon can import credits from a linked Apple/iTunes album only after verifying its UPC against the current MusicBrainz release barcode when present. A dead or mismatched Apple link falls back to Apple catalog `filter[upc]` with strict normalized UPC equality across US, GB, DE, FR, UA, JP storefronts. If neither barcode nor verified Apple link exists, the user gets a clear error, not a guessed album. Album credits remain in Credit Hoarder's single provider pipeline and merged `All` workflow.
- **Direct song workflow parity:** The same import bar provides a collapsed, labeled **Apple Music: single song** option with a URL input (no second button). This reads Apple catalog song metadata and credits by ID, validates the Apple domain, normalizes featuring/punctuation while preserving Remix/Original/Live/etc., and requires one unique MusicBrainz release-track title match (or one unique disc+track slot in a repeated-title case). It maps the result to the exact medium/track position and runs the **same Credit Hoarder review/Instant Fill pipeline** as album imports. In `All` mode the single-song input does not reduce other providers' full-album scope.
- **Work safety parity:** v1.0.58's safety shim was insufficient; it merely refused to create any Work if the title already existed elsewhere. v1.0.59 adds a complete paginated Work title search, author name index narrowing for >8 same-title Works, and verification of `writer`, `composer`, `lyricist` or `librettist` relationships on the candidate. Only one verified existing Work may be reused; when there are no exact same-title Works, stage a new Work of type Song (17), lyrics language unspecified, on the MB recording's canonical title. Inconclusive, failed, partial or ambiguous lookups are manual, **never guess or stage a duplicate**. A persistent-on-page Set prevents a second staged Work of the same normalized title across provider imports. Original Work-import user settings remain visible: **Use works -> create needed** must be selected to stage missing Works; `create none` continues to skip creation.
- **No Beatport addition** or unrelated module changes. All original Toolbox tools remain, including the rule to suppress the Recording data copy buttons on `/edit-relationships`.
- **Tested statically/mocked**, not live in Chrome: 11 Work-lookup tests (zero/one/many candidates, author verification, wrong relation type, incomplete queries, server failures, cross-run staged-title guard); 15 Apple/packaging checks (single song ID, credits, title normalization including Safari Riot remix, strict URL, UPC confirmation and mismatched-link fallback, no guessed album, single icon, keyboard-usable expandable input, other Toolbox modules and syntax); native and standalone script syntax checks.
