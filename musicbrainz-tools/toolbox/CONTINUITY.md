## Product, source, and distribution
- A single Tampermonkey userscript combining MusicBrainz editing helpers. Canonical executable source: `musicbrainz-tools/toolbox/MusicBrainz_ToolBox.user.js`. Native update manifest: adjacent `MusicBrainz_ToolBox.meta.js`. Root `README.md` contains the current pinned installer reference.
- Keep userscript `@name`, `@namespace`, `@downloadURL`, `@updateURL`, and grants stable. Bump `@version` for every code change; mirror version to `.meta.js`, and repin README to a verified script-containing commit. Use Tampermonkey's native update check; no custom update checker.
- Preserve all merged modules: Disc ID auto-selection, cover-art removal, external-link removal, fill dates/worldwide release events, barcode/catalog search, tracklist-versus-recording, recording data to tracks, duplicate edit checking, barcode-versus-linked-release checking, safe recording matcher, linked-provider indicators and associated editing helpers. Never merge Beatport/BPTopTracker importer features into ToolBox.
- A global MusicBrainz request retry layer handles HTTP 503 indefinitely (honor Retry-After; >=5 seconds fallback). Do not bypass it in new requests.
- Browser dependencies: MusicBrainz release/editor UI and web service, Harmony, and Apple Music/Deezer/other public linked providers for applicable lookups. No separate build/install process besides Tampermonkey.
- Persistent state: Tampermonkey GM values (existing modules) and browser localStorage entries under `mb-barcode-link-checker:` for pending release edit tasks (temporary, 1-hour expiry). No local filesystem paths.

## Barcode vs linked releases checker
- Visible on MusicBrainz release-group pages by the Barcode column as "Check barcodes against links"; checks eligible Digital Media releases with barcodes and displays reviewable findings.
- Only treat provider GTIN/UPC as evidence when actually obtained from the linked provider or verified through Harmony; use `equalGtin` normalization. Reverse lookup results must confirm the barcode exactly.
- Do not silently remove unreadable/dead links; manual review is required. A lone provider mismatch may be ambiguous (possibly wrong MusicBrainz barcode) and must not force a change.
- Corrective actions: `replace-wrong-link`, `remove-duplicate-wrong-link`, `move-out`, and `move-in`. Reconcile linked URLs across releases in the same group and preserve the correct target before moving/removing a URL. Open prefilled MusicBrainz release edits for user review; do not submit edits automatically.
- Edit note contract (2026-10-08): the **cause** of removing a mismatched provider URL is the verified barcode difference, *not* the URL also existing on a different MusicBrainz release. For Deezer and any other supported provider, use `Barcode mismatch with <Provider> (MusicBrainz: <old>; <Provider>: <linked GTIN>).` with actual values from linked-page checks. Deduplicate repeated messages. Do not invent GTINs for unreadable providers. Keep other notes concise and include only the ToolBox script link as attribution; drop unrelated Harmony and Apple Music-method citations from the generated edit note. Do not add duplicate "added links" text when a replacement/move-in already accounts for them.
- User-reported regression before 1.0.56: v1.0.55 emitted "Removed a wrongly linked Deezer release URL. The same URL is already correctly linked to: ..." followed by three source URLs; this wrongly presented duplicate linkage as the justification. Fix specifically in `makeEditNote` within the checker module.

## 2026-10-08 - v1.0.58 integrated Credit Hoarder
- **Goal:** Merge *Credit Hoarder* into the *existing one-file MusicBrainz ToolBox* without deleting existing tools, requiring installation of a second script, or adding Beatport/BPTopTracker functionality.
- **Upstream project:** `majkinetor/musicbrainz-userscripts/userscripts/credit_hoarder`; upstream bundled JS blob `3609da1f25cc3ce5c6d4c054c087eafda4dc2134` (distributed source header version `2026.10.7.145215`). It declares `@license MIT`; retain attribution to majkinetor and contributors and link to upstream. The upstream root repository also contains a GPL-3.0 LICENSE; evaluate component licenses again before future redistribution beyond this integration if ambiguity arises.
- **Architecture:** Toolbox's own outer IIFE now runs the complete compiled Credit Hoarder body as a nested IIFE in the **same .user.js**; `MusicBrainz_ToolBox.meta.js` contains only the matching Tampermonkey metadata. The hosted Credit Hoarder module supplies its original import bar, name/alias/source-URL/release-context/co-credit identity review table, manual matching, source links, consolidated multi-provider import, role mappings, deduplication, Instant Fill, diagnostics, title-based remixer extraction, music-publisher/label and place relationships, and its native MB-editor dispatch. Its internal functions and UI remain upstream-style; this is a single-install integration, not a ground-up UI rewrite. Do not install the upstream standalone simultaneously; both attempt to claim `credit_hoarder` and only one may run, depending on version and userscript-manager injection order.
- **Providers:** Apple Music, Discogs, Deezer, Tidal, Qobuz, YouTube Music, Metal Archives, plus title-derived remixers. Upstream feature mode includes context/alias/URL/co-credit matching; users confirm an artist match before it is staged. Qobuz authenticated features still require that provider's existing account setup. MusicBrainz URLs already covered by Toolbox's standard/beta `@match`; extend `@match` for `tidal.com/album/*`, `listen.tidal.com/album/*` and `www.metal-archives.com/albums/*`. Background provider-page runners work through GM storage and the same userscript identity.
- **Work creation guard:** Credit Hoarder upstream only tests whether the **recording** has a linked Work before staging a new one. To preserve the user's no-duplicate policy, Toolbox adds `toolboxVerifyMissingWork` to the bundled `dispatchWorks` creation branch; it checks the full global MusicBrainz Work title query for both original and featuring-stripped forms before allowing creation, refuses to create when exact-title Works exist, when search is incomplete, or when the MusicBrainz API errors. Use Toolbox's native indefinite 503 retry logic and at least 1700ms between Work-guard requests. This intentionally restricts upstream's `Use works -> create needed` behavior when evidence is ambiguous; do not remove or bypass this check. It does not override the independent, more precise Work resolution in `Apple Music works credits -> MusicBrainz` (a separate product outside Toolbox).
- **Review and dispatch:** Source review remains a separate Credit Hoarder import bar on the MusicBrainz relationship editor, but is packaged in the ToolBox userscript. Existing toolbox features (barcodes, recording matching, relationship helpers, artist-credit controls on regular release edit, etc.) stay present. Credit Hoarder stages release/recording/work relationships for user review; it does not automatically submit the current release editor. Explicit right-click/background artist creation is an upstream feature and can submit the separate newly created artist entity after direct user invocation. Do not confuse this with the final release-editor submit.

Restrict Credit Hoarder execution to MusicBrainz, Tidal album and Metal Archives album hosts while existing Toolbox modules keep their previous route gates.
