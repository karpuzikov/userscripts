## User-approved matching contract

1. On a MusicBrainz artist page, a manual `Scan (open Beatport tab)` action paginates **all** release browse results at `/ws/2/release?artist=<MBID>&inc=labels+media+url-rels&fmt=json&limit=100&offset=<N>`. Page offset increases by the **actual** returned release count (MusicBrainz browse can cap a page at 500 tracks).
2. Filter to releases whose every medium is `Digital Media`. Collect existing catalog numbers across **all** digital editions before filtering the candidates.
3. Candidates must have **no** catalog number and at least one UPC/barcode or release-level Beatport URL. An explicit `[none]` is populated metadata and must not be overwritten.
4. With a barcode, **DO NOT query Beatport's public search with a barcode** (v0.1.1 bug). First check a MusicBrainz linked Beatport release, then discover releases by text title on Beatport and validate the UPC from the release metadata. A linked Beatport release is usable only when its actual UPC matches. Each discovered candidate is independently opened; accept only verified `__NEXT_DATA__.props.pageProps.release.upc` and `release.catalog_number` evidence. UPC-12 and EAN-13 leading-zero equivalence up to three zeros; no guess by title. Multiple UPC-verified matches are ambiguous, not auto-picked.
5. Without a barcode, require release-level Beatport links. Read linked pages directly and skip conflicting/missing catalog numbers.
6. Normalize catalog numbers by removing separator punctuation and comparing case-insensitively. If already present on another digital release of the scanned artist **or already queued in the current scan**, skip. This stricter rule is intentional even if distinct editions might legitimately share a catalog number.
7. Otherwise display a review item with release, catalog, Beatport evidence URL, UPC and label. `Review edit` stores a pending proposal and opens the MusicBrainz release editor; **never auto-submit** an edit.
8. On the editor, fill **only** one unique currently empty catalog field; do not overwrite other fields or change the label. Because the tool modifies an edit form, automatically preserve/append a concise Beatport evidence note and the **exact GitHub script URL** when a unique editable edit-note field is found. If the note field is missing or ambiguous, decline auto-fill and allow manual `Copy catalog` and `Copy edit note`. Preserve any existing note text. A user must review label/metadata and submit manually.

## UI/control contract and failure handling

- Artist-page floating dark panel: `Scan (open Beatport tab)` (starts network work, disabled during scan), `Stop scan` (cancels Beatport request, preserves findings), `×` (hides without deleting progress), `♪ Beatport catnos` (reopens), progress/processed count, per-result `Review edit`, `Copy catalog`, evidence URLs, expandable Errors / limitations.
- Release-edit review: `Fill sole empty catalog field` (only unambiguous fields + edit-note), `Copy catalog`, `Copy edit note`, `×` Dismiss. All actions are explicit; only `Review edit` opens a new tab; no MusicBrainz edit is submitted.
- Buttons and links support keyboard and focus states; responsive dark layout; live status; malformed Beatport URLs rejected and text injected only with textContent. Real keyboard/focus/zoom/screenshot acceptance is **NOT RUN**.
- MusicBrainz requests are sequential and at least ~1150 ms apart; HTTP 503 retries indefinitely with Retry-After, >=5s otherwise; non-503 errors fail normally. Beatport metadata is read by a Beatport-origin browser worker tab opened on explicit scan (`GM_openInTab`), with cross-tab Tampermonkey storage/message listeners. It checks Next.js `_next/data` or release `__NEXT_DATA__` by release ID, matching the original Beatport importer. If browser-origin fetch is HTTP 403 or has no release/search result, worker navigates its **own one Beatport tab** to the actual target URL with session correlation and reads hydrated DOM. Scan completion/cancel closes the tab. No API tokens, private APIs, anti-bot bypass, fabricated UPCs or edits. If Beatport itself blocks the browser, report error and leave candidate unverified.

## 2026-10-14 v0.1.2 - browser-origin Beatport reader / fix HTTP 403

- The user reported `Beatport HTTP 403` on public Beatport `/search/releases?q=<UPC>` and `q=<title>`. Root cause: the earlier implementation assumed Beatport public search could discover a release by UPC (not verified) and used `GM_xmlhttpRequest` across origins, sometimes hitting Cloudflare. Beatport public search **is not a UPC lookup**. Do not repeat that strategy.
- The user provided the pinned original Beatport -> MusicBrainz Importer at commit `81388c84f8652d6f371649c1438c4ddc19187b3c`; review of `parseNextData`, `getCurrentPageProps` and `fetchPageProps` established a first-party release metadata source: `__NEXT_DATA__.props.pageProps.release`, and `/_next/data/{buildId}/{locale}/release/{slug}/{id}.json` containing `upc`, `catalog_number`, label, title. v0.1.2 reuses this data model with verified release IDs; importer itself is unchanged.
- New `@match https://www.beatport.com/*`, `GM_openInTab` and GM change listeners. One background tab is opened only after the user presses `Scan (open Beatport tab)` and scan finds eligible releases. Per-scan session keys prevent unrelated Beatport pages from injecting results. Beatport tab is closed on finish/cancel; if initialization fails, show an actionable error. The script does not navigate or modify other Beatport tabs.
- Lookup priority: MusicBrainz-linked Beatport release and exact UPC verification; otherwise Beatport public **text-title** release discovery and UPC verification from each candidate release. With no MB barcode, require a linked Beatport URL. No numeric UPC Beatport search. Results without a verified UPC, multiple UPC matches or a catalog already used by an artist digital release are skipped. No auto-submit.
- On Beatport, worker first tries same-origin Next.js JSON or page fetch. If HTTP 403, empty search-link markup or missing release payload, navigates the dedicated tab to an actual Beatport release/search page and parses its loaded DOM (not an unauthorized Cloudflare bypass). An actual site challenge or redirect may still prevent lookup; do not claim the 403 issue is fully solved without real browser testing.
- UI control changes: one existing Start button now explicitly says it opens Beatport tab; Stop interrupts pending request and closes this tab; status reports tab opening/network stage; no extra duplicate actions. Existing keyboard/control states unchanged; visual hover, screenshot, keyboard, responsive/zoom comparison are **NOT RUN**. UXDT website timed out during this development environment check.
- Automated validation (not real browser): Node syntax PASS, **16 existing JS fixture tests PASS**, **5 new Next.js payload/bridge tests PASS**, **1 mocked end-to-end HTTP 403 -> dedicated browser navigation -> loaded `__NEXT_DATA__` UPC/catalog reply PASS**. These 22 checks are not proof that Beatport's actual browser lets searches succeed. The versioned installer and current mutable source are byte-identical.
