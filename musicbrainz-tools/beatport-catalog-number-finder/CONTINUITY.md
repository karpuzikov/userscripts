## User-approved matching contract

1. On a MusicBrainz artist page, a manual `Scan (open Beatport tab)` action paginates **all** release browse results at `/ws/2/release?artist=<MBID>&inc=labels+media+url-rels&fmt=json&limit=100&offset=<N>`. Page offset increases by the **actual** returned release count (MusicBrainz browse can cap a page at 500 tracks).
2. Filter to releases whose every medium is `Digital Media`. Collect existing catalog numbers across **all** digital editions before filtering the candidates.
3. Candidates must have **no** catalog number and at least one UPC/barcode or release-level Beatport URL. An explicit `[none]` is populated metadata and must not be overwritten.
4. With a barcode, **DO NOT query Beatport's public search with a barcode** (v0.1.1 bug). First check a MusicBrainz linked Beatport release, then discover releases by text title on Beatport and validate the UPC from the release metadata. A linked Beatport release is usable only when its actual UPC matches. Each discovered candidate is independently opened; accept only verified `__NEXT_DATA__.props.pageProps.release.upc` and `release.catalog_number` evidence. UPC-12 and EAN-13 leading-zero equivalence up to three zeros; no guess by title. Multiple UPC-verified matches are ambiguous, not auto-picked.
5. Without a barcode, require release-level Beatport links. Read linked pages directly and skip conflicting/missing catalog numbers.
6. Normalize catalog numbers by removing separator punctuation and comparing case-insensitively. If already present on another digital release of the scanned artist **or already queued in the current scan**, skip. This stricter rule is intentional even if distinct editions might legitimately share a catalog number.
7. Skip Beatport catalog numbers equal to UPC/barcode or a numeric code of UPC/EAN/GTIN length (8, 12, 13 or 14 digits, punctuation ignored). Show these in a separate skipped counter; prioritize safety over numeric-only ambiguous catalog identifiers.
8. Otherwise display a review item with release, catalog, Beatport evidence URL, UPC and label. `Review edit` stores a pending proposal and opens the MusicBrainz release editor; **never auto-submit** an edit. It MUST also seed the verified Beatport release URL as a **purchase for download** external relationship (MusicBrainz link type ID 74) when no existing release relationship points to the same Beatport release ID. Existing links remain untouched.
9. On the editor, automatically fill **only** one unique currently empty catalog field (no second button); do not overwrite other fields or change the label. Because the tool modifies an edit form, automatically preserve/append a concise Beatport evidence note and the **exact GitHub script URL** when a unique editable edit-note field is found. If the note field is missing or ambiguous, decline auto-fill and allow manual `Copy catalog` and `Copy edit note`. Preserve any existing note text. A user must review label/metadata and submit manually.

## UI/control contract and failure handling

- Artist-page floating dark panel: `Scan (open Beatport tab)` (starts network work, disabled during scan), `Stop scan` (cancels Beatport request, preserves findings), `×` (hides without deleting progress), `♪ Beatport catnos` (reopens), progress/processed count, per-result `Review edit`, `Copy catalog`, evidence URLs, expandable Errors / limitations.
- Release-edit review: automatic catalog fill on `/release/<MBID>/edit` after Knockout initializes; passive progress/success/fallback text, `Copy catalog`, `Copy edit note`, `×` Dismiss. There is no extra Fill button. The actual MusicBrainz fields are `#information input[id^=catno-]` with `data-bind: value: catalogNumber`; the edit-note field is `#edit-note-text` (React). If several label/catalog rows exist, fill only on a unique exact Beatport label-name match; otherwise leave untouched for manual review. Never auto-submit. All actions are explicit; only `Review edit` opens a new tab; no MusicBrainz edit is submitted.
- Buttons and links support keyboard and focus states; responsive dark layout; live status; malformed Beatport URLs rejected and text injected only with textContent. Real keyboard/focus/zoom/screenshot acceptance is **NOT RUN**.
- MusicBrainz requests are sequential and at least ~1150 ms apart; HTTP 503 retries indefinitely with Retry-After, >=5s otherwise; non-503 errors fail normally. Beatport metadata is read by a Beatport-origin browser worker tab opened on explicit scan (`GM_openInTab`), with cross-tab Tampermonkey storage/message listeners. It checks Next.js `_next/data` or release `__NEXT_DATA__` by release ID, matching the original Beatport importer. If browser-origin fetch is HTTP 403 or has no release/search result, worker navigates its **own one Beatport tab** to the actual target URL with session correlation and reads hydrated DOM. Scan completion/cancel closes the tab. Human challenge handling: v0.1.4 shows the Beatport worker tab in the foreground when opened, never advances to another page on fixed 25s startup / 30s request expiration, pauses on detected Cloudflare/Turnstile challenges, and resumes the SAME requested release after verification or Stop. No API tokens, private APIs, anti-bot bypass, fabricated UPCs or edits. If Beatport itself blocks the browser, report error and leave candidate unverified.

## 2026-10-14 v0.1.2 - browser-origin Beatport reader / fix HTTP 403

- The user provided the pinned original Beatport -> MusicBrainz Importer at commit `81388c84f8652d6f371649c1438c4ddc19187b3c`; review of `parseNextData`, `getCurrentPageProps` and `fetchPageProps` established a first-party release metadata source: `__NEXT_DATA__.props.pageProps.release`, and `/_next/data/{buildId}/{locale}/release/{slug}/{id}.json` containing `upc`, `catalog_number`, label, title. v0.1.2 reuses this data model with verified release IDs; importer itself is unchanged.

One background tab is opened only after the user presses `Scan (open Beatport tab)` and scan finds eligible releases. Per-scan session keys prevent unrelated Beatport pages from injecting results. Beatport tab is closed on finish/cancel; if initialization fails, show an actionable error. The script does not navigate or modify other Beatport tabs.
- Lookup priority: MusicBrainz-linked Beatport release and exact UPC verification; otherwise Beatport public **text-title** release discovery and UPC verification from each candidate release. With no MB barcode, require a linked Beatport URL. No numeric UPC Beatport search. Results without a verified UPC, multiple UPC matches or a catalog already used by an artist digital release are skipped. No auto-submit.
- On Beatport, worker first tries same-origin Next.js JSON or page fetch. An actual site challenge or redirect may still prevent lookup; do not claim the 403 issue is fully solved without real browser testing.
